## 📌 1. 개요 및 목적

### 1.1 기획 배경 및 사용자 피드백 반영
- 기존에는 **1차 힌트 발언(`hint-turn`)** 중에만 발언자가 `[발언 완료 ➔]` 버튼을 눌러 다음 사람에게 차례를 넘길 수 있었습니다.
- **최후변론(`final-defense`)**, **자기변호(`self-defense`)**, **자유토론(`free-talk`)**, **투표 후 자유토론(`post-vote-free-talk`)** 단계에서는 설정된 타이머(예: 40초, 45초 등)가 끝날 때까지 무조건 기다려야만 했습니다.
- **피드백 반영 (v1.1)**: 다자간 토론은 단 한 명이라도 더 발언이나 추리를 이어가고 싶을 수 있으므로, 조기 종료 기준을 **100% (전원 만장일치)**로 설정하여 모든 참여자가 동의했을 때에만 즉시 다음 단계로 넘어가도록 개선합니다.

### 1.2 목적
1. **1인 발언 시간(최후변론 / 자기변호)**: 현재 발언자 1명이 `[변론 완료 ➔]` 버튼을 눌러 즉시 다음 단계로 진행.
2. **다자간 토론 시간(자유토론 / 투표 후 자유토론)**: 참여 가능한 플레이어 **100% 전원이 `[토론 종료 찬성]`** 버튼을 누르면 즉시 토론이 조기 종료되고 다음 투표 단계로 직행.

### 🔷 2.1 최후변론(`final-defense`) & 자기변호(`self-defense`) 조기 종료 규칙

| 항목 | 상세 규칙 |
|------|-----------|
| **발언 대상자** | 단 1명의 최다 득표자 또는 자기변호 차례인 플레이어 |
| **버튼 노출 위치** | 우측 하단 라이브 패널(`astra-live-panel`) |
| **버튼 명칭** | `⚖️ 변론 완료 ➔` (또는 `🎤 발언 완료 ➔`) |
| **클릭 권한** | **오직 현재 변론 중인 발언자 본인(`turnSpeakerSocketId === myId`)만 클릭 가능** |
| **기타 참여자 화면** | `🔒 [닉네임] 님이 변론 중입니다.` (버튼 비활성화 및 안내 문구 노출) |
| **동작 방식** | 1. 발언자가 버튼 클릭 시 소켓 `pass-defense` 이벤트 송신<br/>2. 서버는 기존 `roomTimers[code]` 타이머를 즉시 해제(`clearTimeout`)<br/>3. 단일 변론이면 즉시 `startPostVoteFreeTalk` 실행, 자기변호면 대기열의 다음 변호자 `startNextSelfDefense` 즉시 실행 |

### 🔶 2.2 자유토론(`free-talk`) 100% 만장일치 조기 종료 규칙

| 항목 | 상세 규칙 |
|------|-----------|
| **참여 대상** | 현재 방에 생존해 있는 모든 유효 플레이어 (탈락자 제외) |
| **버튼 노출 위치** | 우측 하단 라이브 패널(`astra-live-panel`) |
| **버튼 명칭 & 상태** | • 누르기 전: `⚡ 토론 조기 종료 (0/4명)`<br/>• 누른 후: `✓ 조기 종료 동의됨 (3/4명)` (토글 클릭 시 동의 취소 가능) |
| **종료 조건 (100% 기준)** | **`동의 인원수 === 전체 유효 인원수 (100% 전원 동의)`**<br/>• 3명 참여 중: 3명 전원 동의 시<br/>• 4명 참여 중: 4명 전원 동의 시<br/>• 5명 참여 중: 5명 전원 동의 시<br/>• N명 참여 중: N명 전원 동의 시 |
| **동작 방식** | 1. 플레이어가 버튼 클릭 시 `toggle-skip-discussion` 소켓 이벤트 송신<br/>2. 서버에서 동의 목록(`skipDiscussionVotes`) 관리 및 `discussion-skip-updated` 실시간 브로드캐스트<br/>3. **100% 전원 동의 달성 즉시** 기존 자유토론 타이머 해제 및 `vote`(1차 투표) 단계로 즉시 전환! |

---

### 🔷 2.3 투표 후 자유토론(`post-vote-free-talk`) 100% 만장일치 조기 종료 규칙

| 항목 | 상세 규칙 |
|------|-----------|
| **참여 대상** | **최다 득표자(들)를 제외한** 나머지 토론 참여 플레이어 전원 |
| **버튼 노출** | 토론 참여 허용 플레이어에게만 `⚡ 토론 조기 종료 (N/유효인원)` 활성화 |
| **최다 득표자 화면** | `🔒 최다 득표자는 토론에 참여할 수 없습니다.` (버튼 비활성화) |
| **종료 조건 (100% 기준)** | **`동의 인원수 === (전체 인원 - 제외 인원) (토론 참여자 100% 전원 동의)`**<br/>(예: 5명 방에서 1명 지목 시, 나머지 4명 전원이 동의해야 종료) |
| **동작 방식** | 100% 달성 시 즉시 `startFinalDecisionVote`(단일) 또는 `startReVote`(동률) 단계로 즉시 직행 |

## 🔌 4. 소켓 통신 및 데이터 설계

### 4.1 백엔드 방 객체(`room`) 추가 필드
```javascript
room.skipDiscussionVotes = []; // 자유토론 조기종료 동의한 socketId 목록 (단계 전환 시 자동 리셋)
```

### 4.2 신규/수정 소켓 이벤트 명세

| 이벤트명 | 방향 | Payload | 설명 |
|---------|------|---------|------|
| `pass-defense` | Client ➔ Server | `{}` | 현재 발언자가 변론을 즉시 마치고 다음 단계로 넘김 |
| `toggle-skip-discussion` | Client ➔ Server | `{}` | 자유토론 조기종료 동의/취소 토글 송신 |
| `discussion-skip-updated` | Server ➔ Client | `{ skipCount, totalCount, percent, isCompleted }` | 방 전체에 실시간 조기종료 동의 현황 브로드캐스트 |

## 🛡️ 5. 예외 및 엣지 케이스 처리

1. **중도 이탈자 발생 시**:
   - 자유토론 도중 플레이어가 이탈(`disconnect`)하면, 전체 인원수(`totalCount`)와 동의자 목록(`skipDiscussionVotes`)에서 이탈자를 즉시 제거하고 실시간 비율을 재계산합니다. 만약 남은 인원 기준 100%가 충족되면 지체 없이 다음 단계로 넘어갑니다.
2. **페이즈 전환 시 초기화**:
   - `hint-turn`, `free-talk`, `vote`, `final-defense`, `post-vote-free-talk` 등 단계가 바뀔 때마다 서버의 `room.skipDiscussionVotes = []`를 반드시 깨끗이 비워 이전 단계의 투표가 이월되지 않도록 보장합니다.
3. **더블 클릭/중복 전송 방지**:
   - 쿨다운(1초) 및 소켓 토글 처리를 통해 안정적인 상태 동기화를 유지합니다.
